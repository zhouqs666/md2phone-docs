需求与验收 · md 文档手机阅读（2026-09-30）

来源：客户访谈（2026-09-30，书面纪要即本文档）。风险分级说明：全部故事均为 P2（体验类），不触碰资金/隐私/生产数据，验证深度按 A1 取轻。

问题定义

  • 背景与触发：客户在电脑上持续产生 Markdown 文档（如《FDE 工作指南》），只能在电脑上看。
  • 问题陈述：现状——md 文件在手机上打不开、打开也是原始符号；期望——像 App 一样在手机上随时阅读，内容与电脑侧保持一致；差距——离开电脑就看不了，文档写了用不上。
  • 成功度量： 1. 同步动作：电脑侧文档增/改/删后，一次操作（双击或一条命令，≤1 分钟）内完成重建发布，手机端刷新即见结果。人工触发可接受，全自动更好。 2. 阅读体验：390px 宽（iPhone 标准视口）下正文无需横向滚动；字号可调且记住选择。
  • 约束与红线：内容不敏感，允许使用外部云服务与免费托管；规模未定（1 ~ 几十份都要成立）；客户侧自备一个免费托管账号。使用端（客户 2026-09-30 练习②补充）：Android 与 iOS 均需可用，无明确机型——验收矩阵取双端主流浏览器（Android Chrome / iOS Safari）；微信等内嵌浏览器只承诺可阅读，不承诺可安装；跨端差异细节见《实践沉淀/001》实践笔记。
  • 第一版形态（客户 2026-09-30 练习③决定）：不依赖第三方托管、暂不做同步——交付单文件版（整个文档库自包含为一个 HTML，直接发送手机）；同步（故事 3）与 HTTPS 安装桌面（故事 2 AC2）移出第一版，作为升级路径保留，不删故事。
  • 非目标（访谈中与客户确认的口径）：不做全文搜索；不做账号体系/多人协作；不做在线编辑；不替换客户已有知识库工具。
  • 干系人：需求源 / 决策人 / 用户 = 客户本人（本次为演练，由扮演者承担）。

故事与验收标准

故事 1｜在手机上舒服地读一份 md（P2）

价值：作为文档读者，我希望 md 文档在手机上排版良好、字号可调，随时随地能看。

AC： 1. 给定 docs/ 内一份含标题、表格、代码块、引用、列表的 md，当执行构建，then 生成对应阅读页；390px 视口下正文无需横向滚动；表格在自身容器内横向滚动、不撑破页面；代码块同样容器内滚动。 2. 点击「A−/A+」正文字号改变一档（范围 14–24px），刷新后保持（localStorage）。 3. 点击目录按钮展开全部二/三级标题；点击条目跳转至对应小节并收起目录。 4. 断网后，曾经打开过的页面仍可阅读（Service Worker 缓存回退）。

故事 2｜安装到手机桌面（P2）

价值：作为文档读者，我希望像打开 App 一样从桌面图标进入文档库。

AC： 1. 构建产物包含 manifest.webmanifest、192/512 图标与 apple-touch-icon，清单字段完整有效。 2. 经 HTTPS 部署后，Android Chrome 菜单出现「添加到主屏幕」，iOS Safari 经「分享 → 添加到主屏幕」可安装，图标启动后以独立窗口（standalone）打开。 ——AC2 依赖真机与真实托管，本地只能验证 AC1；AC2 列入交付记录的未验证清单。〔练习③起 AC2 移出第一版〕

故事 3｜电脑侧更新同步到手机（P2）〔练习③起移出第一版，升级路径保留〕

价值：作为文档作者，我把 md 放进文件夹、跑一次同步，手机端就能看到最新内容；删除亦然。

AC： 1. 新增：docs/ 放入新 md → 构建 → 首页列表出现该文档，点开内容完整。 2. 更新：修改已有 md → 构建 → 对应页面内容变为新版本，首页「更新时间」刷新。 3. 删除：从 docs/ 移除 md → 构建 → 首页不再出现，产物中该页面文件消失。 4. 自动化：--watch 模式下，docs/ 文件增改删后 5 秒内自动重建；若设置 DEPLOY_CMD，重建后自动执行发布命令。 5. 同步链路：部署到 HTTPS 托管后，手机端刷新即见最新列表。——依赖故事 2 的托管环境，真机验证列入未验证清单。

依赖：客户自备任一免费静态托管（Netlify / GitHub Pages / Cloudflare Pages，README 给出推荐与步骤）。

故事 4｜单文件文档库（P2）〔练习③新增，第一版形态〕

价值：作为文档读者，我希望拿到一个文件就能在手机上读全部文档——不注册、不安装、不联网、不依赖任何第三方服务。

AC： 1. 构建产出单个自包含 HTML（文档库.html）：无外部样式/脚本/网络请求，双击即可在浏览器打开，断网可读。 2. 390px 视口：文档列表与每篇正文均无横向滚动；表格在自身容器内滚动、不撑破页面。 3. 点卡片跳到对应文档；每篇带「目录」可跳转小节；「↑ 文档列表」可返回。 4. 字号 A−/A+ 生效；浏览器允许时刷新后保持。 5. 传输路径：文件经微信/邮件/数据线到达手机后可直接打开阅读。——真机验证列入未验证清单，本地以 file:// 等效验证。

非目标（本版明确不做）：自动同步（更新 = 重发文件）；HTTPS 托管与桌面图标（升级路径，见故事 2/3）。

故事 5｜局域网版：图标 → 列表 → 阅读（P2）〔练习④新增，零第三方〕

价值：作为文档读者，我希望从手机桌面图标点进文档库，看到列表、点开阅读——但不引入任何第三方服务。（练习④客户需求：需要一个图标，点进去能看到文档列表，点击文档打开阅读。）

AC： 1. 电脑侧一条命令（双击 局域网分享.command 或 python3 build.py --serve --lan）启动服务，绑定所有网卡并显示出局域网访问地址。 2. 同一 WiFi 下手机浏览器打开该地址：可见文档列表，点击任一文档进入阅读页。——本地以本机局域网 IP 访问等效验证；真机列未验证清单。 3. 站点含 manifest 与图标文件；「添加到主屏幕」后以图标进入（预期：iOS 全屏 standalone、Android 图标快捷方式）——真机行为列未验证清单。 4. 局域网范围内「准同步」：电脑重新构建后，手机刷新即见最新；与单文件版共用同一内容源（docs/）与构建器，互不冲突。

边界：电脑需开机且手机同 WiFi；离开该网络不可用（此为与托管版的本质差异，交付时向客户讲明）。

故事 6｜安卓 App：图标 → 列表 → 阅读 + 导入更新（P2）〔练习⑤新增；客户确认：interview-prep 壳模式 + App 内导入〕

价值：作为文档读者，我要装一个真正的 App：桌面图标点开就是文档库，离线可读，日常更新不需要重装、不依赖电脑构建链。

AC： 1. 构建流水线产出 文档库.apk（debug 签名，可直接安装）：内置当前全部文档（assets），首次安装开箱即读，全程离线。 2. 点桌面图标 → 文档列表 → 点击进入阅读页；返回键在页内历史回退；390px 视口下阅读体验与网页版一致（字号/目录/表格容器滚动）。 3. App 菜单「导入文档库」：经系统文件选择器选择 文档库.html 后立即切换为所导内容（拷入应用私有目录，重启后仍生效）；菜单「恢复内置」一键回到出厂文档。 4. 内容更新 = 电脑改 md → python3 build.py → 把新的 文档库.html 发到手机 → App 内导入（约 20 秒，不重装）；APK 仅功能升级时重打。

非目标：iOS App（苹果签名门槛，客户确认跟随参考模式结论，iPhone 走 PWA/单文件）；自动同步（局域网拉取列为后续可选）。

验证边界：AC1 静态检查（APK 结构、assets 页面、包名与应用名）与 AC3 代码路径本机可验；AC2/AC3 的真机安装与手势操作列未验证清单。
