需求与验收 · md 文档手机阅读（2026-09-30）

更新于 2026-10-02 00:44 · 约 17 分钟 · 第 3/8 篇

来源：客户访谈（2026-09-30，书面纪要即本文档）。风险分级说明：全部故事均为 P2（体验类），不触碰资金/隐私/生产数据，验证深度按 A1 取轻。

问题定义

  • 背景与触发：客户在电脑上持续产生 Markdown 文档（如《FDE 工作指南》），只能在电脑上看。
  • 问题陈述：现状——md 文件在手机上打不开、打开也是原始符号；期望——像 App 一样在手机上随时阅读，内容与电脑侧保持一致；差距——离开电脑就看不了，文档写了用不上。
  • 成功度量： 1. 同步动作：电脑侧文档增/改/删后，一次操作（双击或一条命令，≤1 分钟）内完成重建发布，手机端刷新即见结果。人工触发可接受，全自动更好。 2. 阅读体验：390px 宽（iPhone 标准视口）下正文无需横向滚动；字号可调且记住选择。
  • 约束与红线：内容不敏感，允许使用外部云服务与免费托管；规模未定（1 ~ 几十份都要成立）；客户侧自备一个免费托管账号。使用端（客户 2026-09-30 练习②补充）：Android 与 iOS 均需可用，无明确机型——验收矩阵取双端主流浏览器（Android Chrome / iOS Safari）；微信等内嵌浏览器只承诺可阅读，不承诺可安装；跨端差异细节见《实践沉淀/001》实践笔记。
  • 第一版形态（客户 2026-09-30 练习③决定）：不依赖第三方托管、暂不做同步——交付单文件版（整个文档库自包含为一个 HTML，直接发送手机）；同步（故事 3）与 HTTPS 安装桌面（故事 2 AC2）移出第一版，作为升级路径保留，不删故事。
  • 非目标（访谈中与客户确认的口径）：不做全文搜索；不做账号体系/多人协作；不做在线编辑；不替换客户已有知识库工具。
  • 干系人：需求源 / 决策人 / 用户 = 客户本人（本次为演练，由扮演者承担）。

故事与验收标准

故事 1｜在手机上舒服地读一份 md（P2）

价值：作为文档读者，我希望 md 文档在手机上排版良好、字号可调，随时随地能看。

AC：

  1. 给定 docs/ 内一份含标题、表格、代码块、引用、列表的 md，当执行构建，then 生成对应阅读页；390px 视口下正文无需横向滚动；表格在自身容器内横向滚动、不撑破页面；代码块同样容器内滚动。
  2. 点击「A−/A+」正文字号改变一档（范围 14–24px），刷新后保持（localStorage）。
  3. 点击目录按钮展开全部二/三级标题；点击条目跳转至对应小节并收起目录。
  4. 断网后，曾经打开过的页面仍可阅读（Service Worker 缓存回退）。

故事 2｜安装到手机桌面（P2）

价值：作为文档读者，我希望像打开 App 一样从桌面图标进入文档库。

AC：

  1. 构建产物包含 manifest.webmanifest、192/512 图标与 apple-touch-icon，清单字段完整有效。
  2. 经 HTTPS 部署后，Android Chrome 菜单出现「添加到主屏幕」，iOS Safari 经「分享 → 添加到主屏幕」可安装，图标启动后以独立窗口（standalone）打开。 ——AC2 依赖真机与真实托管，本地只能验证 AC1；AC2 列入交付记录的未验证清单。〔练习③起 AC2 移出第一版；练习⑦起服务器侧已就绪：HTTPS 托管 https://zhouqs666.github.io/md2phone-docs/ 经公网验证，仅剩真机安装环节〕

故事 3｜电脑侧更新同步到手机（P2）〔练习③起移出第一版，升级路径保留〕

价值：作为文档作者，我把 md 放进文件夹、跑一次同步，手机端就能看到最新内容；删除亦然。

AC：

  1. 新增：docs/ 放入新 md → 构建 → 首页列表出现该文档，点开内容完整。
  2. 更新：修改已有 md → 构建 → 对应页面内容变为新版本，首页「更新时间」刷新。
  3. 删除：从 docs/ 移除 md → 构建 → 首页不再出现，产物中该页面文件消失。
  4. 自动化：--watch 模式下，docs/ 文件增改删后 5 秒内自动重建；若设置 DEPLOY_CMD，重建后自动执行发布命令。
  5. 同步链路：部署到 HTTPS 托管后，手机端刷新即见最新列表。——依赖故事 2 的托管环境，真机验证列入未验证清单。〔练习⑦：服务器侧端到端已实测通过——新增 63s / 删除 73s 反映到公网；真机刷新为最后一步〕

依赖：客户自备任一免费静态托管（Netlify / GitHub Pages / Cloudflare Pages，README 给出推荐与步骤）。

故事 4｜单文件文档库（P2）〔练习③新增，第一版形态〕

价值：作为文档读者，我希望拿到一个文件就能在手机上读全部文档——不注册、不安装、不联网、不依赖任何第三方服务。

AC：

  1. 构建产出单个自包含 HTML（文档库.html）：无外部样式/脚本/网络请求，双击即可在浏览器打开，断网可读。
  2. 390px 视口：文档列表与每篇正文均无横向滚动；表格在自身容器内滚动、不撑破页面。
  3. 点卡片跳到对应文档；每篇带「目录」可跳转小节；「↑ 文档列表」可返回。
  4. 字号 A−/A+ 生效；浏览器允许时刷新后保持。
  5. 传输路径：文件经微信/邮件/数据线到达手机后可直接打开阅读。——真机验证列入未验证清单，本地以 file:// 等效验证。

非目标（本版明确不做）：自动同步（更新 = 重发文件）；HTTPS 托管与桌面图标（升级路径，见故事 2/3）。

故事 5｜局域网版：图标 → 列表 → 阅读（P2）〔练习④新增，零第三方〕

价值：作为文档读者，我希望从手机桌面图标点进文档库，看到列表、点开阅读——但不引入任何第三方服务。（练习④客户需求：需要一个图标，点进去能看到文档列表，点击文档打开阅读。）

AC：

  1. 电脑侧一条命令（双击 局域网分享.command 或 python3 build.py --serve --lan）启动服务，绑定所有网卡并显示出局域网访问地址。
  2. 同一 WiFi 下手机浏览器打开该地址：可见文档列表，点击任一文档进入阅读页。——本地以本机局域网 IP 访问等效验证；真机列未验证清单。
  3. 站点含 manifest 与图标文件；「添加到主屏幕」后以图标进入（预期：iOS 全屏 standalone、Android 图标快捷方式）——真机行为列未验证清单。
  4. 局域网范围内「准同步」：电脑重新构建后，手机刷新即见最新；与单文件版共用同一内容源（docs/）与构建器，互不冲突。

边界：电脑需开机且手机同 WiFi；离开该网络不可用（此为与托管版的本质差异，交付时向客户讲明）。

故事 6｜安卓 App：图标 → 列表 → 阅读 + 导入更新（P2）〔练习⑤新增；客户确认：interview-prep 壳模式 + App 内导入〕

价值：作为文档读者，我要装一个真正的 App：桌面图标点开就是文档库，离线可读，日常更新不需要重装、不依赖电脑构建链。

AC：

  1. 构建流水线产出 文档库.apk（debug 签名，可直接安装）：内置当前全部文档（assets），首次安装开箱即读，全程离线。
  2. 点桌面图标 → 文档列表 → 点击进入阅读页；返回键在页内历史回退；390px 视口下阅读体验与网页版一致（字号/目录/表格容器滚动）。
  3. App 菜单「导入文档库」：经系统文件选择器选择 文档库.html 后立即切换为所导内容（拷入应用私有目录，重启后仍生效）；菜单「恢复内置」一键回到出厂文档。
  4. 内容更新 = 电脑改 md → python3 build.py → 把新的 文档库.html 发到手机 → App 内导入（约 20 秒，不重装）；APK 仅功能升级时重打。

非目标：iOS App（苹果签名门槛，客户确认跟随参考模式结论，iPhone 走 PWA/单文件）；自动同步（局域网拉取列为后续可选）。

验证边界：AC1 静态检查（APK 结构、assets 页面、包名与应用名）与 AC3 代码路径本机可验；AC2/AC3 的真机安装与手势操作列未验证清单。

故事 7｜确认式上传 + App 云端拉取 + 阅读位置记忆（P2）〔练习⑧，客户确认方案后实现〕

价值：作为文档作者，我希望电脑上的更新经我确认后才上传网站；作为读者，我希望在 App 上一键拉取最新内容，并且每个文档都能从上次读到的地方继续。

AC：

  1. 确认门：自动通道检测到 docs/ 变化 → 弹出系统对话框【发布 / 本次跳过 / 本会话不再询问】；跳过 → 不发布且下次变化再次询问；确认 → 发布；「本会话不再询问」后本进程内不再弹窗。手动运行 publish_github.py 视为已确认，不弹窗。（跳过/确认两分支已自动化验证：F1-RESULT PASS；弹窗点击为人工验证项）
  2. 发布侧提供 version.json（内容指纹）与 library.html（整库快照），且站点构建产物确定性可复现（相同 docs → 相同产物 → 指纹一致，跳过守卫有效）。
  3. App 菜单「从网站拉取最新」：比对指纹 → 无更新提示「已是最新」；有更新 → 下载整库快照 → 大小与内容校验 → 原子替换本地副本 → 立即加载并提示大小；失败（无网络/校验不过）不影响本地已有内容。（协议与产物已公网验证；按钮手势真机验）
  4. 阅读位置记忆：多页阅读页按文档记忆滚动位置（百分比），重开恢复；单文件库按「文档 ID + 段内比例」记忆恢复；跨文档互不干扰；记忆仅存本机 localStorage。（Playwright 自动化验证；真机 WebView 手感待验）

非目标：App 后台自动拉取（仅按钮手动）；跨设备位置漫游。

验证结果：F1-RESULT PASS（分支A 跳过/分支B 确认）；F2 协议模拟 PASS（公网端点+校验+落盘+渲染）；F3 见 verify_memory.py 输出。

故事 8｜v1.7 体验升级：搜索、继续阅读、查找与内容形态补强（P2）〔练习⑨·体验复盘新增；访谈非目标中仅「不做全文搜索」一项由本轮复盘解除，账号/协作/在线编辑仍为非目标〕

价值：作为文档读者，我希望文档多了也能快速定位内容、随时接着上次继续读，阅读器具备完整的手感与离线秒开体验。

AC：

  1. 列表搜索：首页搜索框输入关键词 → 按标题/正文过滤卡片，正文命中显示高亮片段与「命中 n/共 m 篇」；清空恢复。索引构建时内联进首页（file:// 与离线可用）。单文件版从 DOM 建索引，Enter 跳到第一篇命中文档并闪烁标记。
  2. 继续阅读：读过某篇（非顶部/结尾）后回列表 → 顶部出现「继续阅读」横幅（最近在读一篇 + 上次位置百分比），点击直达该位置；列表页返回后滚动位置保持，不回顶。
  3. 页内查找：阅读页 ⌕ 打开查找条 → 命中处高亮、显示 n/m、↑↓ 循环定位、× 或 Esc 清除；单文件版作用于全部文档（上限 500 处防卡顿）。
  4. 阅读辅助：目录随滚动高亮当前小节；顶部阅读进度条；代码块一键复制（按钮固定于滚动容器右上角）；正文图片点击灯箱放大；底部「上一篇/下一篇」（单文件版为篇内锚点）。
  5. 外观与字号：◐ 三档（跟随系统/浅色/深色）即时生效且刷新保持；A−/A+ 之间显示当前档位，点击恢复默认 17。
  6. 秒开与更新感知：静态壳（样式/脚本/图标/清单）cache-first，打开不被网络阻塞（HTML 仍 network-first 保证内容最新）；SW 换代激活后向已打开页面广播「内容已更新」提示条（首次安装不弹）。
  7. 图片打包：docs/ 内 md 引用的本地图片，构建后 PWA 版拷入 site/assets/docs// 并改写相对路径；单文件版内嵌 data URI（字节级一致）；随 APK 资产同步。找不到的图片保留原引用并构建时告警。
  8. 安卓 App：文档内外链（http/https/mailto/tel/sms）调起系统应用，App 内仅保留 file:// 导航；「从网站拉取最新」全程进度对话框（连接→下载），可取消且取消不落盘；「导入文档库」校验文件（≥2KB 且含整库标记），选错提示不加载；启动时静默比对版本指纹，不一致才弹窗询问（不自动下载）；夜间主题（values-night）跟随系统，标题栏/状态栏与暗色内容一致。

验证结果：verify_extras.py 34 项 PASS（新增可重复脚本，覆盖 AC1–7）；六套回归全过（build/single/lan/memory/ui/extras）；AC8 为代码路径本机验证 + APK 重打成功，真机手势列未验证清单。

故事 9｜v1.8 阅读体验整改：专家实读审查 14 项问题清零（P2）〔练习⑨二次复盘；以阅读体验专家身份对渲染页面逐屏实读后立项〕

价值：作为文档读者，我希望长文档在手机上"读得进去"——内容不被静默裁切、界面不喧宾夺主、长滚动有节奏有去向。

AC：

  1. 宽内容可发现：表格与代码块两缘在可滑动方向显示渐隐提示；表头允许换行——「可信度图例表」恢复首屏完整可读，流程图裁切处有滑动暗示。
  2. 复制按钮置于代码块上方预留工具位（几何断言：按钮底边 ≤ 代码块顶边），不遮挡任何正文。
  3. 开篇 blockquote 升级为「文档头卡」：从源文本逐行还原字段结构（修复 markdown 软合并导致的粘连），正常字色；仅当正文开头（允许 h1 在前）即该引用块时触发，不误伤普通 callout。
  4. 行内 code 标记加描边，浅色下「已实践/待验证/假设」可信度标记肉眼可辨。
  5. 阅读页顶栏收敛为 ‹ 标题 Aa 🔍 ☰：字号（A−/档位/A+，点档位恢复默认 17）与外观三档收进 Aa 弹出层（点外部/Esc 收起）。
  6. 顶栏下滑隐退、上滑唤出（弹出层/抽屉打开时保持可见）；深滚动时顶栏标题自动切换为当前小节名，回到篇首恢复文档标题。
  7. 长文档辅助：h1 下元信息行（更新时间 · 时长 · 序号/总篇数）；右下角「↑ 回到顶部」深滚动出现；「目录」标题下自带列表压缩渲染；「变更记录」小节折叠为「展开变更记录（N 条）」。
  8. 层级与节奏：h3 带品牌色左侧竖条、h4 加粗；列表条目间距加大、bullet 与文本间距收紧。
  9. 交互修补：目录遮罩层级降至顶栏之下（☰ 可再次点击关闭）；Esc 依次关闭灯箱/查找条/弹出层/抽屉；底部导航语义改为「‹ 较新一篇 / 较早一篇 ›」。
  10. 暗色正文亮度微调（#e6e9ee → #d5dbe3）；首页卡片摘要收紧为单行。
