md2phone · 内容与构建约定（AGENTS.md）

任何会话在本目录工作前，先读本文件。 这是「手机文档库」的内容管线与构建约定，跨会话唯一的执行依据。（体例沿用 interview-prep 工程。）

这是什么

Markdown 文档库，四种形态共用同一个内容源，最终形态是一个 Android App（WebView 套壳 + App 内导入更新）。

内容链路（单向，勿反向手改）：

docs/*.md（源，唯一手改点）→ python3 build.py
    ├→ site/                    （PWA 站点，供托管 / 局域网版）
    ├→ 文档库.html              （单文件版，微信直接发手机）
    └→ android-app/.../assets/web（APK 内置内容）
        → ./gradlew assembleDebug → 文档库.apk

目录结构

路径 作用 是否手改
docs/ 唯一的源文件（md） ✅ 只改这里
build.py 生成器（PWA + 单文件 + APK 资产同步） 一般不改
assets/ 网页模板与样式 一般不改
site/、文档库.html 生成产物 ❌ 由脚本生成
android-app/ Kotlin WebView 壳工程（导入式更新，见 MainActivity.kt 头注释） 一般不改
文档库.apk 打好的安装包 ❌ 由 gradle 产出
verify_build.py / verify_single.py / verify_lan.py 三个形态的可重复验收 改动后必跑

日常内容更新（最常用路径）

  1. 改内容只改 docs/*.md（会被下次构建覆盖的文件不要手改）；
  2. 方式一（推荐）：双击「自动同步.command」→ 弹窗确认「发布」→ 网站自动更新 → 手机刷新或 App「从网站拉取最新」；
  3. 方式二（离线）：python3 build.py → 把 文档库.html 发到手机 → App 菜单「导入文档库」。 ⚠️ App 导入与拉取的永远是整库快照（文档库.html / library.html），不是 .md 原文——App 不解析 md。 ⚠️ 自动通道每次发布需弹窗确认（可选「本会话自动发布」）；手动运行 publish_github.py 视为已确认。

正本与副本（防「改了正本忘了拷」）

docs/ 里有一部分文件是副本，正本在别处：

docs/ 副本 正本位置
FDE-工作指南.md ~/Desktop/FDE-Playbook/FDE-工作指南.md
需求与验收.md、交付记录.md、README.md、AGENTS.md md2phone/ 根目录同名文件
001/002-*.md ~/Desktop/FDE-Playbook/实践沉淀/

规则：改了正本，必须重新拷入 docs/ 再构建，否则库里是旧版本（血泪：指南升到 v0.6，库里的副本还停在 v0.3，被客户一问才发现）。

重打 APK（仅功能升级时；Mac 本机执行，需 Android SDK）

cd android-app
./gradlew assembleDebug
cp app/build/outputs/apk/debug/app-debug.apk ../文档库.apk
  • debug 签名（自动签名可直接安装），个人用途足够，无需 release 签名；
  • gradle.properties 已把 Gradle 指向 Android Studio 内嵌 JDK 21，直接 ./gradlew 即可，勿用系统 JDK 8；
  • gradle 发行版与依赖走本地缓存 / aliyun 源（同 interview-prep），本机可离线构建。

验证纪律

任何 docs/、assets/、build.py 改动后：python3 verify_build.py && python3 verify_single.py && python3 verify_lan.py。 「上一版通过」不证明「这一版结构正确」（血泪：单文件版正文全出血 bug 连过两轮验证才暴露）。

iPhone 说明

苹果不允许直接装安装包；iPhone 走 site/ 托管 PWA（用法 B）、局域网版（A2）或单文件（A）。
